Update ? 13 October 2026: database configuration now uses separate `DB_*` fields. At the user's request, local development supports the existing postgres account only when both the database and app origin are local. This exception has full database privileges, including audit/history access, and supersedes the historical local-runtime statements below. Production still checks and rejects elevated credentials. Integration tests require a separate non-elevated identity and `_test` database.

Date: 12 October 2026, Asia/Colombo. Scope: project requirements/documentation, application pages/components/actions, auth/services/validation, PostgreSQL schema/migrations, setup/seed/recording helpers, tests, environment templates, dependency audit, and local database permissions. The supplied original assessment specifications remain unchanged.

ReserveFlow remains a focused Next.js App Router / TypeScript / PostgreSQL app. Browser forms call thin server actions; services authenticate the actor and own domain validation, ownership, transactions, resource locking, and audit writes. ## Confirmed findings and repairs

| Risk                                            | Repair and evidence                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Overprivileged database configuration           | The actual PostgreSQL 18 app uses `reserveflow_app`; migrations use `reserveflow_owner`; tests use `reserveflow_test_owner`. Startup reads real PostgreSQL role/table/schema permissions and rejects elevated roles, owner-role membership, schema creation, history deletion, and audit modification. Runtime privilege inspection confirmed no schema CREATE, reservation DELETE, or audit SELECT/UPDATE/DELETE; audit INSERT is allowed. |
| Fresh setup lacked audit grants                 | The grant helper now supports both local setup modes and grants audit INSERT plus RateLimit CRUD. Parameterized audit INSERTs omit RETURNING, so private audit data requires no runtime SELECT.                                                                                                                                                                                                                                             |
| Restart/multi-instance login-limit bypass       | Better Auth now uses its PostgreSQL-backed atomic limiter. An integration test sends eight concurrent requests through two instances: five proceed and three are throttled. A newly constructed instance remains throttled.                                                                                                                                                                                                                 |
| Forwarded-IP spoofing                           | All incoming IP headers are ignored by default. An optional trusted header is configured only behind a proxy that overwrites it and prevents direct origin access. The concurrent test rotates forged X-Forwarded-For values without resetting the bucket.                                                                                                                                                                                  |
| Stale actor/role snapshots                      | Mutations take a shared actor-row lock and check current account/role state inside the transaction, before resource/reservation locks. Reservation ownership derives from that locked actor. Stale deactivated/demoted-actor tests reject writes and preserve data.                                                                                                                                                                         |
| Login racing a password/access reset            | Changes update `User.sessionsInvalidBefore` and delete sessions. Server-owned login-start timestamps are checked before session creation, and guards reject sessions older than the cutoff. A real auth test pauses successful password verification across a reset and rejects the old-password login.                                                                                                                                     |
| CSP implementation not applied                  | Proxy moved from root to `src/proxy.ts` beside `src/app`. The production build now recognizes Proxy. Pages render dynamically; forged request nonces/CSP are overwritten. Script/style nonces are fresh per request.                                                                                                                                                                                                                        |
| CSP broke dialogs/streaming                     | The existing scroll-lock dependency receives the initial document nonce via `CspNonce`/`get-nonce`. React's exact `display:none` attribute is hash-allowed; arbitrary inline CSS and inline/eval scripts remain disallowed in production. Browser assertions still check all console/page errors.                                                                                                                                           |
| Insecure non-local environment settings         | Authentication requires a canonical HTTP/HTTPS origin, requires HTTPS for non-local hosts, and rejects placeholder secrets. Remote PostgreSQL connections require `sslmode=verify-full`. HSTS applies to HTTPS production origins; local HTTP previews work.                                                                                                                                                                                |
| Unbounded cloned auth-body buffering            | The route reads the original stream once with an 8 KiB limit and 10-second deadline, then passes a bounded body to Better Auth. Oversized/stalled-body regression tests pass. Auth responses are no-store; unexpected route errors return generic 503 responses.                                                                                                                                                                            |
| Demo credentials targeting an ordinary database | Published demo accounts require both `LOCAL_POSTGRES=true` and the isolated local port 54329. A test rejects port 5432 even with that flag. Private bootstrap refuses subsequent admins and placeholder passwords.                                                                                                                                                                                                                          |
| Test-database aliases                           | Test configuration rejects remote databases, superuser identities, and aliases of the app database. A dedicated test owner was provisioned after verifying the test database was empty. Test fixtures are scoped and removed.                                                                                                                                                                                                               |
| Secret handling gaps                            | The configured secret scan now checks DB-password components, the action-encryption key, and bootstrap passwords. Exposed isolated-cluster role passwords were rotated. Bootstrap entries were removed from the app environment; the existing private login is in the ignored `.local/admin-login.txt` handoff.                                                                                                                             |
| Accidental LAN exposure of a public local demo  | Development/preview servers bind to 127.0.0.1 by default. Deployment binding must be explicitly changed behind the secured reverse proxy.                                                                                                                                                                                                                                                                                                   |

Existing strengths preserved: Argon2id, closed signup/auth operation allowlist, session expiry/cookie protection, strict Zod payload schemas, parameterized SQL, member query scoping, safe public errors, resource FOR UPDATE locking, atomic audit/mutation transactions, logical account deletion, and all handwritten booking constraints.

## Verification and remaining boundaries

Actual final command/browser results and intermediate failures are recorded in [VERIFICATION.md](VERIFICATION.md). This is source review plus local regression testing; it does not establish external deployment or a formal penetration test.

The shared PostgreSQL 18 administrator password previously supplied in chat should be changed privately in pgAdmin. It was not changed automatically because it can affect the user's other databases/applications. The 12 October configuration used a restricted identity. The 13 October local development configuration uses the user-requested postgres identity; production requires restricted credentials.

The full npm audit still reports five high development-toolchain entries from `eslint-config-next` through `braces <=3.0.3` ([upstream advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)); npm's latest braces remains 3.0.3. Its suggested change downgrades the Next.js lint configuration to 14.2.35. The runtime audit is separate; no incompatible downgrade or unreviewed dependency patch was applied. Lint patterns are repository-owned, not user request data.

For deployment, supply runtime credentials only, configure certificate-verified database TLS, secure the proxy/IP-header boundary, provision private accounts, and plan backups/restore, monitoring, audit retention and any required MFA. Those external operations are not part of this local security repair. Without a trusted IP source, a shared per-path login limit can also let one caller temporarily throttle others; configure the secured proxy before exposing the app publicly.
